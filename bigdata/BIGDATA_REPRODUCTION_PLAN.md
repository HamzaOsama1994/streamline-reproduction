## 2. Verified infrastructure facts (from the cloned benchmark repo @ `57524e2`, 2024-08-08)

- **Per-operator parallelism is not available as-is.** Every job builds a Beam pipeline from `FlinkPipelineOptions` (e.g. `etl/.../FlinkJob.java`), which exposes only a **job-wide** `--parallelism`. STREAMLINE's output is a parallelism and placement *per operator*. **This is the main technical risk.**
- **Placement:** Flink cannot pin an operator instance to a named TaskManager. STREAMLINE's "operator → resource R11" decisions must be approximated, e.g. with slot-sharing groups mapped to a TaskManager per resource type, or one session cluster per resource. The paper does not say how it did this. **Decide in week 1 and document it.**
- **Buffer size:** STREAMLINE's "segment size" maps to Flink's `taskmanager.memory.segment-size`, which is set per TaskManager. That matches STREAMLINE grouping operators by segment size before scheduling.
- **The Helm chart** deploys a Flink session cluster through the Flink Kubernetes Operator (`FlinkDeployment`; the operator dependency is commented out, so install it separately), Strimzi Kafka, MongoDB and kube-prometheus-stack. TaskManagers default to 1 CPU / 2 GB / 2 slots.
- **The build** needs JDK 11 and Gradle 8.6. The repo uses Nix flakes, but Gradle can run without Nix. The laptop currently has only Java 8.

## 4. Two options for the parallelism gap (team decision, week 1)

- **A. Native Flink ports (recommended for ETL and YSB).** Re-implement the operator chain in the Flink DataStream API with `setParallelism()` per operator and `slotSharingGroup()` for placement, reusing the repo's operator logic (`RangeFilterFunction`, `BloomFilterTransform`, `Interpolate`, `AnnotationFunction`). This is the most faithful option, and native operators also make per-operator CPU time (ThreadMXBean) easy to collect.
- **B. Beam jobs with job-wide parallelism.** Apply max(STREAMLINE's per-operator parallelism) to the whole job. This is the cheapest option, but it weakens the comparison and must be reported as a major deviation.

A sensible split: A for ETL (5 operators) and YSB (9 operators), and B only as a fallback for STATS.

## 6. Work packages (maps to team roles)

1. **Cluster:** k3d config, Flink Kubernetes Operator, Strimzi, Prometheus; TaskManager pod templates per node type; resource budget. Needs Docker Desktop with WSL2 limits raised in `.wslconfig` (user approval).
2. **Data and workload:** senMlConverter for TAXI and FIT, kafkaProducer replay with the paper's scaling, YSB generator calibration.
3. **Pipelines:** native Flink ports of ETL and YSB (option A); build with JDK 11 and Gradle.
4. **Measurement:** metrics collector (REST + latency markers + ThreadMXBean), profiling grid (parallelism 1–8 × segment size 16k/32k/64k) → real `historical_data` CSVs to retrain the surrogate model.
5. **Control loop:** adapter from STREAMLINE decisions to Flink (parallelism, slot-sharing group, segment size), using savepoint stop-and-restart. Algorithm 5 (seamless update) is not released: report this as a deviation, or implement it as a stretch goal.
6. **Evaluation and report:** statistics, figures, comparison tables, reproducibility discussion (including the code defects and the correction study).
